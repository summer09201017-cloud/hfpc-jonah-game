# 戰爭闖關 #1 ·「摩西舉手之戰」單關設計稿

> 目的:用**最便宜的一關**(~3–4 天)驗證「**戰爭動作關**在這套引擎裡值不值得做」。
> 作法:**重用第二關暴風雨(`storm.js`)的平衡 loop 換皮**,幾乎不寫新物理。
> 經文:**出埃及記 17:8–13**(利非訂與亞瑪力爭戰)+ 17:15(耶和華尼西)。
> 這是「戰爭關卡」系列的第一塊試金石;原型先在約拿引擎 repo 內做(因為要重用 `storm.js`),
> **永久落腳處(獨立戰爭 repo / Paul 原生 / 共用引擎)等手感驗證過再決定**。

---

## 1. 一句話玩法

摩西站在山頂高舉雙手,**手會因疲勞不斷下垂**;玩家要**持續出力把手舉回去**,
撐到**日落**以色列就得勝(17:12「他的手就穩住,直到日落」)。
但**單靠自己撐不到日落**——快垂下時要**呼求亞倫與戶珥來扶手**,才撐得住。

## 2. 核心機制(對照 `storm.js`,標好現成 vs 要新寫)

| 暴風雨的東西 | 摩西舉手換成 | 現成/新寫 |
|---|---|---|
| `tilt` 船傾角 | **手臂下垂角**(0=高舉,越大越垂) | ♻️ 現成(改名) |
| `tiltVel` 角速度 | 手臂下垂的速度 | ♻️ 現成 |
| `tip` 失穩力(越傾越倒) | **疲勞重力**(舉越久越想垂) | ♻️ 現成 |
| `wind` 隨機陣風 | **疲勞陣痛**(隨機讓手一沉) | ♻️ 現成 |
| `player` 玩家施力(←/→ 或點左右半) | **出力舉手**(按住/左右輪流舉左右手) | ♻️ 現成輸入,單手版直接用;雙手版小幅擴充 |
| `capsize` 翻船值 0..1 | **戰局值**:手垂太久 → 亞瑪力得勢,滿 1 = 以色列敗 | ♻️ 現成(改名+改美術) |
| `survival / STORM.duration` | **撐到日落**的倒數 | ♻️ 現成 |
| `stormCast === false` → 撐過即 `win()` | **正是我們要的**:撐到日落直接過關,不要約拿的「拋海」結尾 | ♻️ 現成分支,直接走這條 |
| `flash` 閃電 + 雷聲 | 山下**戰場刀劍交擊**閃光/音效 | ♻️ 現成框架,換音色 |

> **結論:物理 loop、輸入、遊戲迴圈、win/lose、HUD、音效框架、嵌入契約 → 全部現成。**
> **真正要新寫的只有三塊:① renderer 場景美術 ② 亞倫戶珥扶手機制 ③ 數值調校。**

### 要新寫的(這關的成本所在)

1. **renderer 場景(最花時間,約一天半)**:山頂的摩西(向量小人,雙手可舉/垂)、
   左右兩側的亞倫與戶珥、**山下谷中的小型戰場**(以色列 vs 亞瑪力,隨戰局值消長)、
   **太陽位置 = 倒數計時**(從中天走到地平=日落=過關)、兩條 HUD 條(疲勞/戰局)。
   美術用既有向量風格,**山下戰場別做太細**(幾個小人色塊即可,九成效果一成成本)。
2. **亞倫戶珥扶手(這關的靈魂,約半天)**:見下方依靠值。
3. **`config.js` 新增 `MOSES` 數值區 + 手感調校(約半天~一天)**:疲勞重力、陣痛強度、
   出力大小、扶手降低衰減的幅度與次數、日落總時長(建議單局 **60–90 秒**)。

## 3. 依靠值鉤子(反向 RPG —— 別人抄不走的那一味)

| 一般遊戲會這樣做 | 你這關要這樣做 |
|---|---|
| 玩家自己手動撐久,撐越久越強 | **單靠自己,手臂疲勞超快、必定垂下**——靠己必敗 |
| 加 buff / 升級讓自己更耐 | **呼求亞倫與戶珥扶手**(同工):點「求助」鍵,兩人來架住摩西的手,
衰減大幅變慢——但**有次數/冷卻**,逼你學會「在對的時候倚靠群體」 |
| 純靠玩家反應 | 信息:得勝不是靠你手有多穩,是靠**神 + 神所賜的扶持**(亞 4:6「不是倚靠勢力,不是倚靠才能」) |

**過關經文卡**(一張就好,輕量):
出 17:11「**摩西何時舉手,以色列人就得勝;何時垂手,亞瑪力人就得勝。**」
+ 17:15「**耶和華尼西(耶和華是我的旌旗)**」。

## 4. 操作

- **手機**:按住畫面左半舉左手、右半舉右手(沿用 `storm` 的 `pointerX < viewW*0.5` 判半邊);
  **雙指同時按住=雙手齊舉**。「求助」用一顆畫面上的大按鈕(或雙邊同時長按觸發)。
- **電腦**:←/→ 舉左右手(沿用 `input.left/right`),空白鍵=求助。
- 先做**單軸版**(一條「舉手高度」)最省;**雙手版**(左右各一條)更有戲,小幅擴充,看 day 1 進度決定。

## 5. 關卡節奏 / 階段

- 只需要 `storm` 的 **`ride` 階段**;**不要 `cast/thrown`**(那是約拿專屬)。
- 直接走 `stormCast === false` 的「撐過 duration → `win()`」分支。
- 難度隨時間升(`windGrow` 換成「越接近日落,手越酸、陣痛越兇」),最後 15 秒最緊張。

## 6. 過關 / 失敗

- **過關**:撐到日落(survive 到 duration)→ 以色列得勝(約書亞殺敗亞瑪力,17:13)→ 經文卡 → `win()`。
- **失敗**:戰局值(capsize)累積到 1 → 亞瑪力得勝 → 可重來(動作關允許失敗重試)。
- 計分:剩餘疲勞/扶手沒用完的程度 → score,給嵌入回傳 `onComplete({won,score,level})`。

## 7. 內容 / 題目(刻意輕量,別塞爆審題佇列)

- 這關的「內容」= **場景 + 一張過關經文卡**,**不配問答題**(或最多 1 題反思)。
- 理由:你之前點出的審題瓶頸——動作關的價值在手感,不在題量,先別加重閘門負擔。

## 8. 嵌入契約對齊(之後要進 Paul 當闖關站時)

- 場景做成**自成一格的 class**(完全比照 `Storm`:`constructor(game)`/`reset()`/`step(dt)`)。
- `ui` 由外注入、`embed` 旗標守住嵌入分支、結束走有嵌入分支的 `win()/gameOver()`、
  `destroy()` 停 loop+`input.detach()`+停音樂、HUD 兩端文字走 `hudLabels`/`_hudOverride`。
- 純 Canvas 關(像 1/2/4)→ 宿主注入 `NullUI` 即可,**不需要卡片 EmbedUI**。
- 真正接進 Paul 時:給新的 minigame id、加進 `embedLevel` 白名單與 `boot()` 派發、棋盤上用 `add-challenge-station` 加一座戰爭站。
- **驗證階段先單機跑**,不必馬上接 Paul。

## 10. 風險 / 注意

- **扶手別做成自動贏**:扶手太強 = 無腦,要給次數/冷卻,讓「何時求助」成為決策。
- **平衡換皮的手感**:`storm` 的 `invertControl`/`push`/`damp` 要重調,別直接沿用船的數值。
- **山下戰場別過度美術**:向量色塊小人即可,別在驗證關投入精細美術。
- **這關是 Exodus 內容、暫住約拿 repo**:只是為了重用 `storm.js` 做原型;永久落腳處等驗證後再定,別現在糾結架構。
